# FloatGPT: System Architecture & Feature Documentation

This document serves as the definitive guide to FloatGPT, detailing its core features, system architecture, design decisions, and backend infrastructure. It is designed to provide a comprehensive, copy-paste-ready explanation for stakeholders, developers, and architects.

---

## 1. Project Overview

**FloatGPT** is a production-grade, distributed AI assistant designed for both Desktop (via Electron) and Web (Playground). It aims to deliver "Calm Execution" through a minimalist, floating UI (the "Orb") while packing a highly complex, fault-tolerant, and low-latency AI orchestrator under the hood. 

Unlike standard chat wrappers, FloatGPT operates as an **agentic system**, capable of generating structured plans, routing intents, managing multimodal context, and synchronizing state across devices using a local-first approach.

---

## 2. Core Features

### 2.1. The "Orb" & Calm Execution (UI/UX)
- **Floating Desktop Interface**: Built with Electron, the app lives as a floating, always-on-top "Orb" that can expand into a full workspace.
- **Physics-Based Animations**: Utilizes `framer-motion` for fluid, physics-bound micro-interactions, ensuring a premium feel.
- **Aesthetic Focus**: Deep, muted backgrounds with high-contrast text, strictly avoiding chaotic colors unless indicating critical warnings.

### 2.2. Multi-Provider AI Orchestration
- **Agnostic Provider Support**: Seamlessly integrates with Groq, OpenAI, Anthropic (Claude), and Google (Gemini).
- **Thinking Mode**: Supports deep-reasoning models (e.g., DeepSeek R1, OpenAI o3-mini, Claude 3.7 Sonnet) for complex analytical tasks.
- **Multimodal Ingestion**: Native support for dragging and dropping images, PDFs, and text files directly into the context window.

### 2.3. Agentic Planning & Execution
- **Structured JSON Generation**: When tasked with creating or updating plans, the AI generates strict JSON representing Tasks, Goals, Projects, and Risks.
- **Web Search Integration**: Uses Google Gemini's native search grounding to fetch real-time information when required.
- **Task Tracking**: An integrated workspace to track active, planned, and completed tasks generated by the AI.

## 3. System Architecture & Design

FloatGPT employs a modern, distributed architecture combining a thick Electron client with a Serverless/Edge-compatible backend API.

### 3.1. High-Performance Request Pipeline
- **Zero-Latency Intent Routing**: Bypasses slow LLM-based intent classifiers by using a deterministic Regex/Keyword router to instantly categorize user prompts (e.g., distinguishing a chat query from a command like `/goal`).
- **Tiered Distributed Caching**:
  - **L1 In-Memory LRU Cache**: Hashes prompts and context (SHA-256) to instantly serve repeated local queries.
  - **L2 Upstash Redis Cache**: A globally distributed REST-based Redis cache ensures that if one client solves a complex query, others benefit instantly, without the overhead of heavy TCP connections.
- **Server-Sent Events (SSE) Streaming**: Natively streams tokens directly to the frontend (`ChatPanel.tsx`), ensuring progressive UI rendering and eliminating perceived latency.

### 3.2. Reliability & Fault Tolerance
- **Circuit Breaker Pattern**: Continuously monitors the health of AI providers. If a provider (e.g., Groq) experiences an outage, the circuit trips, automatically routing traffic to a fallback provider (e.g., OpenAI) without user intervention.
- **Idempotency Keys**: Protects backend endpoints from duplicate mutations (e.g., preventing a network stutter from creating duplicate tasks) using a fast in-memory idempotency store.
- **In-Memory Rate Limiting**: Protects the API from abuse using a sliding-window rate limiter.

### 3.3. State Management & Synchronization
- **Local-First Priority**: Uses `Zustand` for reactive UI state and `idb-keyval` (IndexedDB) for blazing-fast local reads/writes.
- **Debounced Firestore Sync**: Synchronizes cross-device state using Firebase Firestore. Write operations are carefully debounced to prevent database spamming and preserve free-tier limits.
- **Strict State Isolation**: The Desktop app and Web Dashboard share a sync layer but maintain independent session states to prevent transcript overwriting.

### 3.4. Serverless Background Processing
- **Upstash Kafka Message Queue**: Heavy, non-blocking tasks (such as background conversation summarization) are pushed to a distributed Kafka queue rather than blocking the main Electron thread.
- **Webhook Consumers**: The Express backend acts as a webhook consumer (`/api/worker/summarize`), processing Kafka payloads asynchronously using Serverless worker patterns.

## 4. Technology Stack

- **Frontend Application**: React 19, Vite, Tailwind CSS v4, Framer Motion.
- **Desktop Wrapper**: Electron (with secure IPC bridging and bounded window constraints).
- **Backend API**: Node.js / Express (Serverless-ready).
- **State & Persistence**: Zustand (Memory), IndexedDB (Local), Firebase Firestore (Cloud Sync).
- **Caching & Queues**: Upstash Redis (REST API), Upstash Kafka.
- **AI Infrastructure**: LangChain-inspired custom orchestrator with unified provider adapters.

## 6. Summary for Stakeholders

FloatGPT is built for **speed, resilience, and scale**. By implementing Enterprise-grade patterns—like Circuit Breakers, Tiered Caching, Kafka-backed asynchronous workers, and debounced local-first state synchronization—FloatGPT ensures an uninterrupted, premium user experience. It leverages managed infrastructure (Firebase, Upstash) to remain highly cost-effective while delivering the architectural robustness expected of top-tier AI applications.
